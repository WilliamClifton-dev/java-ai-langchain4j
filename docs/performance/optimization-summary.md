# HBTI Coach 项目优化总结

> 历史分析材料，最初记录于 2026-09-17。文中延迟、存储节省和容量数字属于估算或目标，不是可引用的基准测试结果。当前测量方法见 [RELEASE_EVIDENCE.md](../RELEASE_EVIDENCE.md)；在固定环境执行并保存报告前，不应将预测表格描述为已实现收益。

## 已实施的结构性改进

- Flyway 迁移为追踪查询加入 `(user_id, local_date)` 复合索引。
- 会话消息增加保留期限和分批清理策略。
- 仓库包含 k6 L1 脚本，可在固定环境运行后记录延迟、错误率和 dropped iterations。

## 评估边界

索引能改变查询计划，不自动证明端到端延迟改善。实际结论应附：数据规模、数据库版本和资源规格、查询计划、基线与优化后样本、p50/p95/p99，以及对应 commit SHA。

任何“支持 N 个用户”“节省 N%”的表述都需要独立负载或存储测量，不从索引复杂度、脚本阈值或理论估算推导。

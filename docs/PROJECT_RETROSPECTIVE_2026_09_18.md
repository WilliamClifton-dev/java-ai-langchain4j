## 1. 复盘结论

项目已经从“AI 对话 Demo”推进到可复现的 L1 公共测试版：核心用户路径、确定性健康计算、AI 工具授权、认证与数据归属、流式韧性、离线评估、备份恢复和回滚演练均已落地。当前最有价值的工程成果，是把模型能力限制在解释和对话，把计划、测评、追踪、复盘、授权和持久化交给确定性服务。

项目当时的主要短板是交付证据和生产边界仍需继续收紧：Compose smoke 在 CI 中是非阻塞任务，公开部署所需的平台证据尚未形成完整链路。后续状态变化见当前状态报告。

## 3. 做得好的地方

### 3.1 AI 边界设计清晰

项目没有把“让模型决定一切”当作产品方案。模型只能解释、追问、总结或选择显式允许的工具；用户归属、参数校验、幂等、事务、权限和写入结果由服务端决定。这个边界同时降低了幻觉、越权和不可审计写入的风险，也是后续扩展新场景时最应该保持的约束。

### 3.2 领域模型和数据生命周期有工程纪律

MySQL 作为事实源，Flyway 采用追加式迁移；用户拥有的数据在查询层带归属条件；测评、计划、周报和知识版本具有明确生命周期。Redis 被限定为限流、短租约和可重建缓存，避免把关键事实放进临时状态系统。

### 3.3 测试覆盖了高风险路径

测试不仅验证普通成功路径，还覆盖了认证与令牌轮换、资源归属、幂等、工具授权、流式超时/熔断/取消、模型故障隔离、知识检索、数据清理、OpenAPI 契约和迁移。该复盘对应的当时记录为后端 175 个测试（2 个跳过）、前端 32 个测试和前端生产构建通过；这些数字是 2026-09-18 的历史快照，不代表当前主线结果。

### 3.4 文档和运行手册形成了连续链路

ADR、架构文档、API 示例、故障排查、部署最佳实践、数据保留、备份恢复、回滚、AI 安全评估和发布清单已经覆盖开发到运维的主要环节。近期提交也显示团队在安全依赖升级、CI action 升级和发布证据建设上保持了连续投入。

## 4. 可以改进的地方

### 4.1 “生产就绪”表述需要分层

状态文档使用了“生产就绪”和“安全评分 A+”等强结论，但仓库自身同时写明项目仍是 L1 公共测试版，公开部署还缺 TLS、托管密钥、异地加密备份、告警和已发布镜像 digest 证明。后续应统一为“核心功能与 L1 证据就绪；受控生产部署待平台证据完成”，避免让读者把测试环境结论理解为全面生产认证。

### 4.2 非阻塞 Compose smoke 会削弱交付信号

当时 CI 中 `compose-smoke` 设置了 `continue-on-error: true`。当前已调整为 Pull Request 和 `main` 上阻塞失败，普通 feature branch push 不运行；后续应根据失败证据修复环境问题，而不是弱化发布门禁。

### 4.3 版本升级债务应从“评估”进入执行

Spring Boot 3.5 已 EOL，升级评估文档已经完成，但实际主线仍是 3.5.16。应把升级拆成可回滚的小批次：先建立兼容性分支和基线，再处理 Spring Security、LangChain4j、Flyway、SpringDoc、测试切片和容器运行时，最后用同一套离线评估、L1 负载、恢复和回滚证据验收。

### 4.4 当前工作区改动需要尽快收口

复盘时未提交改动包括生产配置校验、HTTP 安全响应头、Coach 内存策略集中化、知识检索策略集中化、MySQL 性能索引和测试 profile 修复。后续分支已为这些改动补充定向测试；当前实现和证据见项目状态报告与最新 CI。

### 4.5 指标需要从静态承诺转向持续采集

文档给出了启动时间、P95、L1 并发等指标，但复盘时缺少统一的基线文件、采集时间、环境规格和趋势对比。后续应将关键指标写入发布证据：API P50/P95/P99、首 token 延迟、流式并发拒绝率、数据库慢查询、Redis 命中率、错误码分布和资源使用峰值。

## 5. 根因分析

| 现象 | 主要根因 | 解决方向 |
|---|---|---|
| 生产就绪表述偏强 | 产品状态、L1 证据和平台部署条件写在不同文档，缺少统一分级 | 建立“开发 / L1 / 受控生产 / 公开生产”状态矩阵 |
| Compose 偶发失败只能非阻塞 | CI 环境启动时间和依赖服务就绪存在波动，缺少稳定的发布环境 | 固化镜像、延长并细化探针、在发布流水线阻塞验收 |
| 升级长期停留在评估 | 升级涉及基础框架、AI SDK 和安全组件，缺少阶段性验收门 | 用小批次迁移，每批绑定测试和回滚证据 |
| 工作区改动未收口 | 性能、安全和配置硬化并行推进，缺少“变更冻结—验证—提交”节奏 | 按主题拆分提交，并为每批建立验证记录 |

## 7. 复盘后的验收标准

- 主线测试：后端无失败、前端无失败，跳过项有明确原因。
- 发布流水线：Compose smoke 在发布路径阻塞失败；失败可定位并产生证据。
- 安全：OSV 与前端依赖审计无高危发现；生产 profile 配置验证有自动化测试。
- 可运维：备份恢复、回滚、健康探针和告警在暂存环境实际演练。
- 可追溯：每次发布都能从 commit SHA 追到迁移版本、镜像 digest、测试报告和配置摘要。
- 产品边界：所有健康事实仍由确定性服务写入，模型不能绕过授权工具和用户归属。
